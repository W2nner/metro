# METRO — инструкция для проверяющих

## 1. Запуск панели

Ubuntu 22.04, Docker:

```sh
docker build -t metro-detector .
mkdir -p output
docker run --rm -p 127.0.0.1:8190:8190 \
  -v /absolute/path/to/data:/data:ro \
  -v "$PWD/output:/output" \
  metro-detector serve --data /data --host 0.0.0.0 --state /output/state
```

Откройте http://localhost:8190. В контейнере путь к подключённым данным начинается с `/data`. Панель принимает загрузку файлов и без --data. История хранится в `/output/state/detections.sqlite3`; сохраняйте volume между запусками.

Альтернатива: положите данные в `./data`, выполните `docker compose up --build`, откройте тот же адрес. Compose предназначен для файлов; для физического ROS 2-лидара используйте `--network host` на Linux.

Windows, Python 3.10+:

```powershell
python -m pip install -r requirements.txt
python -m metro_detector serve --data D:/lidar/lidar-review --state state
```

Повторный локальный запуск: `start-panel.cmd`. Он автоматически найдёт соседнюю папку `lidar-review/pcd`, если она существует. Установка зависимостей нужна один раз; runtime не обращается к сети.

## 2. Одно облако или папка

Во вкладке «Обнаружение» нажмите «Загрузить облако». Поддержаны:
- PCD: binary или ASCII; binary_compressed пока не поддерживается;
- PLY: ASCII, binary little/big endian, поля vertex x/y/z;
- XYZ: первые три числовые колонки, разделитель — пробел;
- CSV: x,y,z (в любом порядке при наличии заголовка), либо первые три числовые колонки.

Координаты — метры. Лимит загрузки одного файла — 256 MiB. Файл обрабатывается целиком; отображение ограничено 150 тысячами точек. Невалидные XYZ и нулевые возвраты исключаются. Загруженные облака сохраняются в state/uploads и доступны после перезапуска вместе с историей. Сохраняйте папку state между запусками.

Для папки нажмите «Bag / поток ROS 2» → «Папка облаков на сервере». Путь должен находиться внутри --data. Интерфейс не открывает произвольные файлы компьютера.

## 3. ROS 2 bag

Папка SQLite3 bag, отдельный .db3 или .mcap читаются через rosbags без установленного ROS. В панели выберите режим bag, путь, «Найти топики», PointCloud2-топик и «Подключить». Bag с сырыми UDP-пакетами сначала требует декодирования драйвером лидара.

Панель воспроизводит запись по её timestamp. Если детектор отстаёт, очередь сохраняет только свежий кадр. Счётчик пропусков виден в панели. Для полного анализа **без пропуска кадров**:

```sh
docker run --rm -v /absolute/path/to/bag:/data:ro \
  -v "$PWD/output:/output" metro-detector \
  process /data --bag --topic /sensing/lidar/hesai128/pointcloud \
  --output /output/detections.jsonl
```

Если PointCloud2-топик ровно один, `--topic` можно опустить. Тот же `process` без `--bag` принимает файл или папку облаков.

## 4. Физический LiDAR / ROS 2-трансляция

Нужен драйвер датчика, публикующий `sensor_msgs/msg/PointCloud2`. Вход алгоритма — XYZ и необязательный ring; intensity сейчас не используется. Карта и одометрия для детекции не обязательны.

Для Hesai официальный драйвер: https://github.com/HesaiTechnology/HesaiLidar_ROS_2.0 . Следуйте его инструкции по сборке и задайте IP, UDP-порт и калибровочные файлы вашего устройства. Для ROS 2 Humble запуск драйвера указан производителем как `ros2 launch hesai_ros_driver start.py`. Проект детекции сам не настраивает сетевой интерфейс и не декодирует сырые UDP-пакеты.

```sh
ros2 topic list -t
ros2 topic hz /lidar_points
# тот же ROS_DOMAIN_ID и совместимая DDS-сеть
docker run --rm --network host -e ROS_DOMAIN_ID=0 \
  -v "$PWD/output:/output" metro-detector serve \
  --host 0.0.0.0 --state /output/state
```

Затем в панели выберите живой ROS 2 и фактическое имя топика. Подписка BEST_EFFORT / KEEP_LAST depth 1. Результаты также публикуются в `/metro/obstacles` (`std_msgs/msg/String`, JSON). В режиме без панели:

```sh
docker run --rm --network host -e ROS_DOMAIN_ID=0 \
  metro-detector ros --topic /lidar_points
ros2 topic echo /metro/obstacles
```

Для совместимости с ROS 2 используйте Linux host networking; особенности Docker Desktop DDS не обходятся пробросом одного HTTP-порта. Панель не имеет аутентификации: публикуйте её только в доверенной локальной среде, не в интернете.

Для интеграции без ROS есть локальный HTTP-вход `POST /api/live/upload?name=scan.pcd&timestamp_ns=...` с содержимым PCD/PLY/XYZ/CSV в теле. `GET /api/live/frame` отдаёт согласованную пару JSON-результат/облако и счётчики. HTTP не является драйвером физического датчика.

## 5. Калибровка и выход

Настройки по умолчанию соответствуют предварительной оценке ваших записей: −Y вперёд, +Z вверх; габарит 2.1 × 3 м. Для иной установки задайте `forward_axis`, `up_axis`, `yaw_deg`, `lateral_offset_m`, высоту и self_masks. Пример — `config/default.json`. Конфигурацию можно загрузить во вкладке «Подключение» или передать `--config file.json` после команды serve/process/ros.

`obstacle` и `distance_m` — наличие выбранной тревоги и евклидово расстояние до ближайшей измеренной точки. `status=UNCERTAIN` не означает свободный путь. `nearby_objects` — геометрические кластеры снаружи расчётного габарита, не семантическая классификация людей.

Режим single использует один кадр; confirmed требует 2 попадания в окне 3 кадров. Неидущий вперёд timestamp и разрыв больше 0.5 с сбрасывают подтверждение. При скачке по кадрам в панели история детектора сбрасывается.

## 6. Карта и история

«Карта пути» содержит демонстрационный маршрут, станции, условный поезд, повороты, 2D/3D и ручной прогресс. Движение примера независимо от LiDAR. Реальной локализации нет. Можно загрузить маршрут CSV/XYZ, JSON `{"points":[[x,y,z],...]}`, GeoJSON с одной LineString (WGS84 преобразуется в приближённую локальную сетку метров), либо 3D-карту PCD/PLY. После загрузки 3D-карты без маршрута положение поезда остаётся неизвестным.

«История обнаружений» сохраняет тревожные кадры, расстояния, результат, параметры и отметки оператора. Есть фильтры, CSV, JSON и переход к доступному исходному кадру. Повторное открытие одинакового результата не создаёт новую строку. История считает кадры, **не уникальные объекты**. Отметки «верное/ложное» используются только для просмотра и не меняют детектор. Удаление state потеряет историю — держите резервную копию.

## Проверка установки

`python -m metro_detector doctor` проверяет зависимости. `python -m metro_detector inspect /path/to/bag` показывает топики. В ROS-контейнере доступен launch: `ros2 launch /app/launch/metro.launch.py topic:=/lidar_points`.

Текущие результаты Docker, ROS/DDS и полного прогона приведены в reports/RELEASE_VALIDATION.md. Физический лидар не подключался. Калибровка, дальность 150+ м и качество на приватных данных остаются отдельными нерешёнными ограничениями.

Для просмотра сохранённой тревоги нажмите «Смотреть в 3D» в истории или красную точку карты. Позиции отметок на демонстрации условные. Метки «ложное» скрывают событие с карты, но не удаляют из журнала и не меняют детектор. Версия 0.4.2 проверена полными прогонами 13 759 кадров в Windows и Linux; подробности в отчёте.
